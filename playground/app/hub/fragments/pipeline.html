파이프라인 — 레지스트리에서 Storybook, Storybook에서 페이지까지 2026-09-16 개정

1 레지스트리
ds-registry.json — 컴포넌트의 단일 목록. 스토리 파일 1개 = 항목 1개(이름 · 상태 · 스토리 · 피그마 세트 · 노트). Storybook 에 있는 것이 곧 DS다. approved.json·vocab-map.json 은 여기서 생성되는 호환 뷰(클론용). 피그마 Component 페이지는 만드는 곳(새 컴포넌트·상태를 먼저 그리고 FE 초기 셋업에 넘긴다), 코드에 들어오면 스토리가 기준이 된다.
2 Storybook
/storybook/ — 팔레트·시맨틱·타이포(Foundations), 페이지 템플릿(Templates), 컴포넌트(DS) 를 한곳에서 본다. 보는 곳. 코드와 피그마가 다르면 Storybook 이 진실이고 pnpm registry --audit 가 피그마 쪽을 잡는다.
3 페이지 생성
저장소를 클론한 폴더에서 Claude Code 세션에 바로 채팅한다 — CLAUDE.md 계약이 자동 적용되어 프레임을 묻고 Storybook 컴포넌트·365 토큰만으로 뼈대 페이지를 만든다(기본·빈·로딩·에러 4개 상태). DS 에 없는 컴포넌트는 shadcn 기본형으로 대체하고 마커로 표시하며, 생성이 끝나면 미채택 목록·프롬프트·정적 HTML 을 담은 Jira DES 티켓이 자동 발행된다 — 디자이너가 DS 편입 여부를 판정한다. 절차는 「사용방법」의 빠른 시작 참고.

토큰 파이프라인

원천
dstk/*.json — W3C DTCG 표준, core → semantic 참조 구조.
산출
pnpm ds:build → CSS 변수(dist/dstk.css) + Tailwind 프리셋 → playground·생성 페이지가 사용. 빌드·커밋은 관리자만.
365 토큰
ds365.json — 365 DS 카탈로그의 토큰·값 조정 기록(현재 1차: 네이비·각짐). 값이 확정되면 dstk로 편입한다.
Foundations
팔레트 · 시맨틱(Theme × dstk 대조표) · 타이포는 Storybook Foundations에서 본다 — 같은 dstk JSON 을 렌더한다. 사이트의 표는 2026-09-16 은퇴.

파이프라인 — 레지스트리에서 Storybook, Storybook에서 페이지까지 2026-09-16 개정

1 레지스트리
ds-registry.json — 컴포넌트의 단일 목록. 스토리 파일 1개 = 항목 1개(이름 · 상태 · 스토리 · 피그마 세트 · 노트). Storybook 에 있는 것이 곧 DS다. approved.json·vocab-map.json 은 여기서 생성되는 호환 뷰(클론용). 피그마 Component 페이지는 만드는 곳(새 컴포넌트·상태를 먼저 그리고 FE 초기 셋업에 넘긴다), 코드에 들어오면 스토리가 기준이 된다.
2 Storybook
/storybook/ — 팔레트·시맨틱·타이포(Foundations), 페이지 템플릿(Templates), 컴포넌트(DS) 를 한곳에서 본다. 보는 곳. 코드와 피그마가 다르면 Storybook 이 진실이고 pnpm registry --audit 가 피그마 쪽을 잡는다.
3 페이지 생성
저장소를 클론한 폴더에서 Claude Code 세션에 바로 채팅한다 — CLAUDE.md 계약이 자동 적용되어 프레임을 묻고 Storybook 컴포넌트·365 토큰만으로 뼈대 페이지를 만든다(기본·빈·로딩·에러 4개 상태). DS 에 없는 컴포넌트는 shadcn 기본형으로 대체하고 마커로 표시하며, 생성이 끝나면 미채택 목록·프롬프트·정적 HTML 을 담은 Jira DES 티켓이 자동 발행된다 — 디자이너가 DS 편입 여부를 판정한다. 절차는 「사용방법」의 빠른 시작 참고.

원천

산출
pnpm ds:build → CSS 변수(dist/dstk.css) + Tailwind 프리셋 → playground·생성 페이지가 사용. 빌드·커밋은 관리자만.
365 토큰
ds365.json — 채택 카탈로그의 365 토큰·값 조정 기록(현재 1차: 네이비·각짐). 값이 확정되면 dstk로 편입한다.

레퍼런스 구현 스택

레퍼런스 구현 스택: React + Tailwind + shadcn/ui 계열. 화면 이해(시각 스펙)용이며, 토큰 JSON은 중립이므로 다른 스택 제품도 토큰을 가져다 쓸 수 있다.

토큰 표는 「시맨틱」 한 장으로 합쳤다(2026-09-15) — 피그마 Theme 대조와 dstk 토큰이 같은 표다.

무엇

관리 위치
컴포넌트 원천은 ds-registry.json(2026-09-15 — 「Storybook 컴포넌트」가 그 뷰, 채택은 status 로), 토큰·값 조정은 「365 DS」, 레이아웃 프레임은 「페이지 템플릿」, 기획 입력 기록은 「히스토리」 — 모두 365 탭.
현재 상태
Storybook 컴포넌트 47종 · Foundations·Templates 문서 · /storybook/ 배포(2026-09-16). 다음: PageHeader·Stepper·HeatmapGrid 편입, MCP 연결, 생성 자동 Jira.

팔레트 — 유일한 색 원천 dstk/palette.json · 피그마 fill 실측

번호는 밝기가 아니라 역할(50=배경 · 100=면 · 900=최대 대비) — 시맨틱이 번호만 참조하면 조명 모드 전환이 자동이다. ★ = 대비 인증 앵커(Day=600 · Dusk·Night=500).

공통 시맨틱 — Theme × dstk 대조표

한 표(2026-09-15 병합): 이름 = dstk 토큰 = Tailwind 클래스(피그마 폴더 General/는 뺐다) · 모드 셀 = 스와치 + 팔레트 칩 이름(피그마 Colors 이름 그대로) + hex · 비고 = 피그마 그룹(Tint · Chart · Product)·번들. 원천 dstk/figma-theme-snapshot.json — ds:build가 시맨틱과 대조 검증 후 게시한다. Theme 밖 dstk 토큰(상태 축·램프·비색상)은 아래쪽에 이어진다.
값 직접 기입 금지 — 전부 팔레트 참조(빌드 게이트가 강제).
상태-토큰 매핑(상태 이름 ≠ 토큰 이름): WARNING(심각)=destructive · CAUTION(주의)=warning · UNREAD(미확인)=info · NORMAL(정상)=success — 위계 빨강 > 주황 > 파랑 > 초록.

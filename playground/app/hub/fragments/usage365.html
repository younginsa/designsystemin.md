세션으로 화면 만드는 법(클론·채팅·DS 요청)의 정본은 HINAS DS 탭 「사용방법」.
이 페이지는 프론트 연동 전용이다 — CSS 핸드오프 · 스톡 shadcn과의 차이 · 연결 방법.

CSS 핸드오프

받기
⬇ handoff.zip 다운로드 — 프론트 4파일 세트.

개별 열람·복붙:
primitives.css — 컬러 팔레트 원천(값은 이 파일만 소유)
semantic-token.css — 팔레트 → 시맨틱 매칭(var 참조)
typography.css — Desktop 타이포 10종(Inter)
index.css — shadcn·Tailwind 매핑(배선)
구조
값은 primitives가 단독 소유한다.
시맨틱은 var() 참조 사슬 — dstk를 갱신하면 자동 전파된다.
교차 조명 핀은 --dusk-red-600 패턴 프리픽스.
갱신 · 버전
push마다 같은 URL이 항상 최신.
버전 확인 = 각 파일 첫 줄 주석(커밋 · 날짜).
개별 컴포넌트
02 「365 DS」 카드 헤더 우측 「코드」 → 우측 드로어. 코드 탭 = 파일별 원문(접기 · 파일별 복사 · 전체 복사), 스펙 탭 = cva에서 자동 추출한 variant × state × classes 표(값은 코드 원문 클래스 그대로 · 마크다운 복사). 딥링크 #code=<슬러그>.

왜 스톡 shadcn 설치로는 재현이 안 되나

① 문법 수정분
Button 추가 variant(destructive-outline · destructive-ghost · xs).
Table 내장 라운드 래퍼 · 행 hover 제거.
✓ 우측 셀렉트 문법 등.
② 자체 프리셋
shadcn에 없는 프리셋 12종가량 —
FilterBar · SearchBox · NotificationPanel · ErrorState · StatePreview · DetailPanel · IconSelect · RowsPerPage 등.
③ 토큰 값
변수 이름만 shadcn과 동일하고 값은 dstk 빌드다.

Storybook 작업대 (스파이크 · 로컬 전용)

역할 분리 — Storybook은 컴포넌트 작업대(상태·변형·측정), 이 허브는 정본(어휘 · 템플릿 · 문서 · 갤러리). 권한은 approved.json에만 있다. 2026-09-08 Button 1종으로 검증, 확대는 FE의 스토리 작성 합의 후.

실행
pnpm storybook → http://localhost:6006. 배포하지 않는다(로컬 전용).
스토리 파일
components/src/ui/<컴포넌트>.stories.tsx — CSF 형식이지만 @storybook/*을 import 하지 않는다(순수 객체). 그래서 02 카드도 같은 파일을 읽는다(previews.tsx의 fromStories()). 스토리를 추가하면 카드에 저절로 나타나고, 지우면 조용히 빠진다.
규약
parameters.vocab = 채택 어휘 슬러그(btn-basic 등). 카드 목록은 approved.json이 돌리므로 미채택 슬러그를 적은 스토리는 허브에 나오지 않는다(Storybook에는 「미채택」 배지로 나온다).
argTypes = 컨트롤 패널 선택지(cva 정의와 동일하게).
__namedExportsOrder = 선언 순서(모듈 export는 알파벳순이라 필요 · 실제 Storybook은 컴파일러가 자동 생성).
조합형(ButtonGroup 묶음 등)은 render — 컨트롤은 포기.
툴바 · 패널
Mode = Light — Cloud · 365 / Dark — SVM · NAS / Control(래퍼 클래스 전환, 토큰은 허브와 동일).
Measure · Outline = hover 박스 모델(px). Controls = variant · size · disabled 실시간. Docs = 타입에서 props 표. Accessibility = axe(대비 기준 4.5 — 허브 aux 3:1 정책과 다르니 판단 전까지 참고만).
주지 않는 것
토큰 이름·3모드 값 표·타이포 역할명·어휘 게이트·페이지 템플릿 — 전부 이 허브에만 있다. Storybook은 8px라고 말하고, 허브는 radius-md라고 말한다.

사용법 — 세션에서 바로 생성

1 클론 (최초 1회)
git clone github.com/younginsa/designsystemin.md — 저장소 읽기 권한과 본인 계정으로 로그인한 Claude Code만 있으면 된다. 토큰은 각자 좌석에서 쓴다.
2 폴더에서 실행
클론한 폴더에서 claude 실행. 규칙(CLAUDE.md)·채택 어휘(approved.json)·365 토큰(ds365.json)이 자동 적용되고, 세션이 시작할 때 git pull로 항상 최신 DS를 받는다.
3 채팅
화면 스크린샷·와이어프레임을 드래그하고 "메인 레이아웃 본문에 넣어줘"처럼 말한다 (영역 이름: 메뉴·상단바·본문). 뼈대가 먼저 나오고, 채팅으로 그 자리에서 다듬는다(재생성 없음). 모든 화면은 기본·빈·로딩·에러 4개 상태를 포함한다.
결과물
본인 로컬 playground/app/generated/<이름>/에 남는다 — 커밋하지 않고 각자 팀에서 활용한다. 화면만 볼 사람에겐 "HTML로 줘"로 뽑은 정적 파일만 전달하면 된다(설치 불필요). 채택 목록 밖 컴포넌트가 필요하면 세션이 만들지 않고 자리표시 후 보고한다.
DS 요청
쓰다가 필요한 게 생기면 세션에 "DS 요청: ○○ 추가 필요"라고 말한다 — Jira DES 보드로 티켓이 올라가고(본인 계정, 최초 1회 API 토큰 설정 필요), 디자이너가 반영해 커밋하면 모두에게 자동 배포된다. 자리표시가 발생하면 세션이 먼저 올릴지 물어본다.

프론트 구현 연결 — shadcn 기반 확인·전달물

생성 화면은 공통 DS 시맨틱 토큰만 쓴다(임의 hex·dark: 0건 — self-check 게이트로 강제). 렌더 기본은 :root=Light 값 — 화면 코드가 Light를 하드코딩하는 게 아니라 토큰을 참조하므로, .dark 클래스 하나로 코드 수정 없이 재스킨된다. 컴포넌트는 shadcn 구조(Radix + Tailwind v4 + cva, 변수명도 shadcn 규약)라 shadcn을 아는 프론트라면 그대로 읽고 쓸 수 있다 — 단 스톡 shadcn 설치(npx shadcn add)로는 재현이 안 된다. 아래 전달물을 복사해 쓴다.

스톡 설치가 안 되는 이유
① 스톡 컴포넌트의 문법 수정분 — Button 추가 variant(destructive-outline·destructive-ghost·xs), Table 내장 라운드 래퍼·행 hover 제거, ✓ 우측 셀렉트 문법 등 ② shadcn에 없는 자체 프리셋 12종가량 — FilterBar·SearchBox·NotificationPanel·ErrorState·StatePreview·DetailPanel·IconSelect·RowsPerPage 등 ③ 토큰 값이 dstk 빌드(변수 이름만 shadcn과 동일).
CSS 핸드오프
⬇ handoff.zip 다운로드 — 프론트 4파일 세트. 값은 primitives가 단독 소유하고 시맨틱·타이포·shadcn 매핑이 var 사슬로 연결된다(dstk 갱신 = 자동 전파). 브라우저 열람·복붙: primitives.css · semantic-token.css · typography.css · index.css. push마다 자동 최신 — 버전은 각 파일 첫 줄 주석(커밋·날짜)으로 확인.
전달물 4개
components/src(@ds/ui 소스 — 레지스트리 대신 이걸 복사) · dist/dstk.css(제품별이면 dist/products/*.css) · 화면 코드(playground/app/generated/*) · 규칙 문서(design.md·ds365.json)
의존성
tailwindcss@4 · radix-ui · class-variance-authority · lucide-react · tailwind-merge+clsx(cn 유틸)
배선
전역 CSS에 dstk.css import(그거면 토큰 끝 — :root=Light라 기본 라이트) → @ds/ui 경로 alias(tsconfig paths) → 컴포넌트는 우리 소스 그대로, 임의 수정 금지.
모드
다크/컨트롤 필요 시 래퍼에 .dark / .theme-control 클래스만 — 화면 코드는 불변.

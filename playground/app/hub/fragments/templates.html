템플릿 — 레이아웃 프레임을 번호로 고르는 선례

레시피는 페이지 유형이 아니라 레이아웃 프레임이다. 세션이 애매한 레이아웃을 만나면 "어느 프레임의 본문인가, 단독 화면인가"를 이 목록의 번호로 물어본다 — 여기 카드와 모달 선택지의 번호는 항상 같다 (원천: layout/ 목록 순서). 본문 내용은 요청자가 가져오는 스크린샷·와이어프레임이 결정한다.

1 HiNAS 365 메인 레이아웃
HiNAS 365 ⊞메뉴계정 · 접기
상단바
본문 — 요청한 화면이 들어가는 곳
2컬럼 — 풀하이트 사이드바(상단 브랜드·하단 계정/접기) + 상단바(시계·알림) + 본문. 표준 요청 문장: "스샷을 메인 레이아웃 본문에 넣어줘". 레이아웃에 안 담기면 단독 화면. hover = 실물 미리보기 · 클릭 = 실물 열기.

본문 패턴 — 본문 영역의 구성 선례 (문자 매김)

프레임 안 본문의 선례다 — 프레임 번호와 조합해 "① 프레임 + C 본문"처럼 쓴다. 고정 요소(하단 바 포함)는 본문 컬럼을 벗어나지 않는다 (원천: layout/body-patterns.md).

A 리스트
타이틀 행 → FilterBar → Table → 푸터(고정). 필터=FilterBar 전담 · 헤더=정렬 전담, 목록 액션은 actions 슬롯. 푸터 「페이지당: [15˅] │ 전체 N건」(보조 카운트 괄호). 빈 결과 = Empty(조건 초기화). hover = 실물 미리보기 · 클릭 = 실물 열기.
B 상세
좌측 요약 패널(kv) + 우측 본문(아코디언·탭·타임라인). 브레드크럼에 개체명. hover = 실물 미리보기 · 클릭 = 실물 열기.
C 위저드
하단 바 — 본문 폭 안
상단 스테퍼 + 단계별 폼 + 하단 이전/다음 바 — 사이드바를 덮지 않는다. hover = 실물 미리보기 · 클릭 = 크게 보기(잠금 해제 후).
D 대시보드
카드 캔버스 — bg-secondary·p-8 + 무보더 카드(shadow-card). 표준 조립: KPI 카드 행(3·4개 gap-4) → 타이틀+테이블 카드(variant=plain), 섹션 리듬 space-y-6. hover = 실물 미리보기 · 클릭 = 실물 열기.
E 프로그레시브 폼
하단 고정 바 — bg-secondary
조건 노출 단일 페이지 생성 폼 — 가운데 정렬 max-w-4xl. 게이트 충족 시 다음 섹션 자동 노출(점선 = 대기 섹션, 미충족 CTA disabled). 카드형 라디오 그리드 · 개체 연결은 Popover+Command([+ 새로 만들기] 모달) · sticky 하단 바(bg-secondary). 단계 강제면 C, 단순 입력이면 Dialog. hover = 실물 미리보기 · 클릭 = 실물 열기.

템플릿 — 레이아웃 프레임을 번호로 고르는 선례

레시피는 페이지 유형이 아니라 레이아웃 프레임이다. 세션이 애매한 레이아웃을 만나면 "어느 프레임의 본문인가, 단독 화면인가"를 이 목록의 번호로 물어본다 — 여기 카드와 모달 선택지의 번호는 항상 같다 (원천: layout/ 목록 순서). 본문 내용은 요청자가 가져오는 스크린샷·와이어프레임이 결정한다.

상단바
본문 — 요청한 화면이 들어가는 곳
2컬럼 — 풀하이트 사이드바(상단 브랜드·하단 계정/접기) + 상단바(시계·알림) + 본문. 표준 요청 문장: "스샷을 메인 레이아웃 본문에 넣어줘". 레이아웃에 안 담기면 단독 화면. hover = 실제 화면.

본문 패턴 — 본문 영역의 구성 선례 (문자 매김)

프레임 안 본문의 선례다 — 프레임 번호와 조합해 "① 프레임 + C 본문"처럼 쓴다. 고정 요소(하단 바 포함)는 본문 컬럼을 벗어나지 않는다 (원천: layout/body-patterns.md).

A 리스트
검색·필터 툴바 + 테이블 + 페이지네이션. 빈 결과는 Empty(조건 초기화). hover = 실제 화면.
B 상세
좌측 요약 패널(kv) + 우측 본문(아코디언·탭·타임라인). 브레드크럼에 개체명. hover = 실제 화면.
C 위저드
하단 바 — 본문 폭 안
상단 스테퍼 + 단계별 폼 + 하단 이전/다음 바 — 사이드바를 덮지 않는다. hover = 실제 화면.
D 대시보드
카드 캔버스 — gray-10 배경 + 무보더 카드(shadow-card) + 스탯·타이틀·경량 표(variant=plain) 카드. hover = 실제 화면.

사용법 — 세션에서 바로 생성

1 클론 (최초 1회)
git clone github.com/younginsa/designsystemin.md — 저장소 읽기 권한과 본인 계정으로 로그인한 Claude Code만 있으면 된다. 토큰은 각자 좌석에서 쓴다.
2 폴더에서 실행
클론한 폴더에서 claude 실행. 규칙(CLAUDE.md)·채택 어휘(approved.json)·365 토큰(ds365.json)이 자동 적용되고, 세션이 시작할 때 git pull로 항상 최신 DS를 받는다.
3 채팅
화면 스크린샷·와이어프레임을 드래그하고 "메인 레이아웃 본문에 넣어줘"처럼 말한다 (영역 이름: 메뉴·상단바·본문). 뼈대가 먼저 나오고, 채팅으로 그 자리에서 다듬는다(재생성 없음). 모든 화면은 기본·빈·로딩·에러 4개 상태를 포함한다.
결과물
본인 로컬 playground/app/generated/<이름>/에 남는다 — 커밋하지 않고 각자 팀에서 활용한다. 화면만 볼 사람에겐 "HTML로 줘"로 뽑은 정적 파일만 전달하면 된다(설치 불필요). 채택 목록 밖 컴포넌트가 필요하면 세션이 만들지 않고 자리표시 후 보고한다.
DS 요청
쓰다가 필요한 게 생기면 세션에 "DS 요청: ○○ 추가 필요"라고 말한다 — Jira DES 보드로 티켓이 올라가고(본인 계정, 최초 1회 API 토큰 설정 필요), 디자이너가 반영해 커밋하면 모두에게 자동 배포된다. 자리표시가 발생하면 세션이 먼저 올릴지 물어본다.

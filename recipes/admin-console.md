# recipe: ① 관리 콘솔 프레임

## 언제 쓴다
HiNAS 365 내부 화면 전부 — 리스트·상세·대시보드·설정·다단계 입력 등,
"로그인한 운영자가 좌측 메뉴로 오가며 쓰는 화면"이면 기본값으로 이 프레임이다.
본문에 무엇이 오는지는 프레임과 무관하다 — 사용자가 준 스크린샷·와이어프레임이
본문 내용을 결정한다. ("업로드한 스샷을 관리 콘솔 본문에 넣어줘"가 표준 요청 문장.)

## 영역 — 요청·수정 지시에서 이 이름으로 부른다
- **메뉴(사이드바)**: 좌측 고정 내비(그룹 라벨·아이콘, `Sidebar` collapsible="none").
  메뉴 구성을 모르면 묻지 말고 원본 제품 구조(운영/호선 관리/업데이트/관리)를 기본값으로 쓴다.
- **상단바**: 브레드크럼 좌측, 우측에 시계·알림·아바타.
- **본문**: 셸 안 전폭(`SidebarInset` + `p-8`), 페이지 제목 `text-2xl font-bold`
  + 우측 주요 액션 버튼(페이지당 primary 1개). 사용자가 준 화면이 이 영역에 들어간다.

## 본문 관례 노트 — 본문 유형별 선례 (프레임과 별개, 강제 아님)
- **리스트**: 검색(`InputGroup`)+필터 툴바 → `Table`(2줄 링크 셀·칩·상태 도트) → `Pagination`.
- **상세**: 브레드크럼에 개체명 추가, kv 카드(`Item` 조합)·아코디언·탭 조합.
- **다단계 입력(위저드형)**: 상단 `Stepper`(완료 체크·현재 강조·미래 muted),
  단계당 하나의 폼 영역(섹션 라벨 + `Field` 그리드), 하단 고정 바(좌측 "커밋 전
  저장되지 않음" 안내 muted, 우측 [이전] outline·[다음/검증하고 계속] primary),
  마지막 단계는 검토 요약(입력 값 kv 나열 + 단계별 수정 링크).
  1~2단계 입력이면 일반 폼 또는 `Dialog`로 충분하다.

## 언제 안 쓴다
- 인증·랜딩·문서형 페이지, 외부 공유용 단독 뷰(리포트 출력 등)
  → **단독 화면**(프레임 없음, 중앙 정렬 카드 또는 프로즈 폭)

# AI 친화 디자인 시스템 설계서

- 날짜: 2026-07-29
- 상태: 승인됨 (텍스트 우선 A안 채택)
- 대상: Avikus 사내 AI 디자인 시스템 (Figma + Claude)

## 목표

자연어 한 문단(예: "어드민이 회원 관리하는 테이블 리스트 페이지, 유저 추가 시 해당 유저의 로그인 페이지, 로그인 후 수치·지표 메인 페이지 만들어줘")을 입력하면:

1. 디자인 시스템을 준수하는 **동작하는 목업 페이지**(코드)가 생성되고,
2. 사람이 보고 승인하면,
3. 해당 화면이 **피그마에 정식 디자인 산출물로 기록**된다.

우선순위는 코드 > 디자인. 피그마는 기록 보관소(하류)다.

## 확정된 요구사항

| 항목 | 결정 |
|---|---|
| 산출물 | 코드 우선. 승인된 화면을 피그마에 기록 (둘 다, 코드 > 디자인) |
| 기존 자산 | 피그마·코드에 조금씩 있으나 정리 안 됨 → 수확 후 정규화 |
| 주 사용자 | 디자이너, 개발자, 기획/PM 등 전 직군 |
| 기술 스택 | 여러 스택 혼재 → 토큰은 프레임워크 중립, 목업은 React 기준 |
| 비개발 직군 접점 | claude.ai + 커넥터, design.md를 지식으로 첨부해 사용 |

## 핵심 원칙

1. **단일 원천**: git 저장소 하나(design.md + tokens + components + recipes)가 진실의 원천. 피그마 라이브러리, 목업 코드, claude.ai용 문서는 전부 여기서 파생되는 산출물이다.
2. **텍스트 우선**: AI가 가장 잘 읽는 형식은 마크다운 + JSON. 피그마 캔버스를 매번 MCP로 읽는 방식은 쓰지 않는다.
3. **선택지 제한**: 시맨틱 토큰과 등록된 컴포넌트만 사용 가능. 임의 값(hex, arbitrary spacing) 금지. 이 제약이 일관성을 만든다.
4. **레시피 기반 조립**: 반복되는 페이지 유형을 레시피로 문서화하고, 자연어 요청을 레시피 매칭 → 컴포넌트 조립으로 처리한다.
5. **단방향 동기화**: 코드 → 피그마. 피그마에서의 직접 수정은 원천에 반영되지 않는다. 규칙 변경은 저장소에서 한다. (팀 공지 필요한 운영 규칙)

## 저장소 구조

```
design-system/
├── design.md               # AI 규칙서 — 시스템의 헌법
├── CLAUDE.md               # Claude Code용 절차 지침
├── tokens/
│   ├── core.json           # 원시 값: 팔레트, 타입 스케일, 간격 스케일 (W3C DTCG)
│   └── semantic.json       # 의미 토큰: bg-surface, text-primary, border-danger…
├── components/
│   ├── ui/                 # Button, Input, Table, Card, Badge, Dialog… (~15개)
│   └── patterns/           # DataTable+툴바, StatCard 그리드, AuthForm 등 조립 패턴
├── recipes/
│   ├── admin-list.md       # 어드민 테이블 리스트 페이지
│   ├── auth.md             # 로그인/가입 페이지
│   ├── dashboard.md        # 수치·지표 대시보드
│   └── form-detail.md      # 상세/편집 폼 페이지
├── playground/             # Next.js 앱 — 생성된 목업 미리보기
├── dist/
│   ├── design-standalone.md  # claude.ai 첨부용 단일 문서 (자동 생성)
│   └── tokens.css / tailwind # Style Dictionary 산출물
└── scripts/
    ├── build-tokens.ts     # 토큰 → CSS 변수 / Tailwind / 피그마 Variables
    └── build-standalone.ts # design.md+토큰+레시피 → 단일 문서
```

레퍼런스 구현 스택: React + Tailwind + shadcn/ui 계열. 목업·승인용이며, 토큰 JSON은 중립이므로 다른 스택 제품도 토큰을 가져다 쓸 수 있다.

## design.md 구성 (AI 규칙서)

사람용 가이드라인이 아니라 AI에게 내리는 명령문 형태로 작성한다.

1. **강제 규칙**: 색·간격·라운드·그림자는 시맨틱 토큰만 사용. 임의 값 금지 (`#3B82F6`, `p-[13px]` 등).
2. **컴포넌트 카탈로그**: 컴포넌트마다 {언제 쓴다 / 언제 안 쓴다 / props / 예시 코드} 블록.
3. **페이지 레시피 인덱스**: 요청 유형 → 레시피 매핑 표.
4. **레이아웃 규칙**: 사이드바/헤더 셸, 그리드, 반응형 브레이크포인트.
5. **금지 목록(안티패턴)**: 그라데이션 남발, 카드 안의 카드, 임의 그림자 등 AI가 습관적으로 저지르는 것들.

레시피 형식 예 (admin-list): 사이드바 셸 + 페이지 헤더(제목, 주요 액션 버튼) + 필터 툴바 + DataTable + 페이지네이션. 각 구역에 사용할 컴포넌트와 토큰을 명시.

## 토큰 파이프라인

- 원천: `tokens/*.json` (W3C DTCG 표준, core → semantic 참조 구조)
- 산출 3갈래 (`build-tokens.ts`, Style Dictionary 기반):
  1. CSS 변수 + Tailwind 프리셋 → playground/목업용
  2. 피그마 Variables (라이트/다크 모드 포함) → Figma MCP로 주입
  3. design-standalone.md 내 토큰 표 → claude.ai용

## 생성 워크플로우

### Claude Code 경로 (개발자·디자이너)

CLAUDE.md가 절차를 강제한다: 페이지 생성 요청 → design.md + 해당 레시피 읽기 → playground에 페이지 생성 → 기계 검증(lint) → dev 서버 미리보기 제공 → 스크린샷 셀프 리뷰.

### claude.ai 경로 (기획/PM)

사내 claude.ai 프로젝트에 `design-standalone.md`를 지식으로 첨부. 대화로 요청하면 React 아티팩트로 미리보기. standalone 문서에는 아티팩트 제약 대응 지침 포함(토큰을 CSS 변수 블록으로 인라인, 컴포넌트는 문서 내 스니펫 사용). 결과가 채택되면 개발자/디자이너가 Claude Code 경로에서 정식 목업화한다.

## 피그마 기록 파이프라인

- **1회 셋업**: 토큰 → 피그마 Variables 생성, 핵심 컴포넌트 → 피그마 컴포넌트 라이브러리 생성 (figma-generate-library 워크플로우). Code Connect로 피그마 ↔ 코드 컴포넌트 매핑.
- **화면 기록**: 승인된 목업 → 라이브러리 컴포넌트 인스턴스 + Variables 바인딩으로 화면 조립 (figma-generate-design 워크플로우). 하드코딩 값 없는 정식 산출물.
- **재동기화**: 토큰/컴포넌트가 변경되면 피그마 Variables·라이브러리를 재생성.

## 기존 자산 수확 (Phase 0)

기존 피그마 파일·코드베이스에서 실제 사용 중인 색/타이포/간격/컴포넌트를 인벤토리로 추출 → 중복 통합, 명명 정리 → 토큰과 컴포넌트 목록 초안으로 확정. 발명이 아닌 정규화.

## 품질 검증

- **기계 검증**: ESLint 커스텀 룰 또는 스크립트로 임의 색상·간격 값 검출. 생성 직후 자동 실행.
- **시각 검증**: 생성 후 스크린샷을 Claude가 셀프 리뷰 (정렬, 대비, 오버플로). CLAUDE.md 절차에 포함.
- **사람 승인**: 최종 게이트. 승인된 것만 피그마에 기록.

## 단계별 로드맵

| 단계 | 내용 | 완료 판정 |
|---|---|---|
| 0 | 기존 자산 수확 → 토큰 확정 | tokens/*.json 확정, 팀 리뷰 통과 |
| 1 | design.md + 레퍼런스 컴포넌트 ~15개 + playground | 단일 페이지 생성이 일관되게 나옴 |
| 2 | 레시피 4종 + Claude Code 워크플로우(CLAUDE.md, lint) | 예시 프롬프트가 한 번에 3페이지 목업으로 나옴 |
| 3 | 피그마 파이프라인 (Variables·라이브러리·화면 기록) | 승인 화면이 피그마에 정식 산출물로 기록됨 |
| 4 | claude.ai 접점 (standalone 빌드 + 프로젝트 셋업) | 기획자가 대화만으로 아티팩트 목업을 뽑음 |

## 성공 기준

자연어 한 문단 요청 → 어드민 리스트 + 로그인 + 대시보드 3페이지가 디자인 시스템을 준수하는 동작하는 목업으로 생성되고, 승인 시 피그마에 라이브러리 기반 산출물로 기록된다.

## 범위 제외 (v1)

- 피그마 → 코드 역방향 동기화
- 프로덕션 npm 패키지 배포 (목업·승인용 레퍼런스 구현까지만)
- React 외 스택용 컴포넌트 구현 (토큰만 중립 제공)
- 사내 전용 웹 툴 (claude.ai로 대체)

AI 친화 디자인 시스템 설계서

승인됨 — 텍스트 우선 A안 2026-07-29 Avikus 사내 · Figma + Claude

1목표

자연어 한 문단을 입력하면 —

1
디자인 시스템을 준수하는 동작하는 목업 페이지(코드)가 생성되고,
2
사람이 보고 승인하면,
3
해당 화면이 피그마에 정식 디자인 산출물로 기록된다.
예시 프롬프트: "어드민이 회원 관리하는 테이블 리스트 페이지, 유저 추가 시 해당 유저의 로그인 페이지, 로그인 후 수치·지표 메인 페이지 만들어줘"
우선순위는 코드 > 디자인. 피그마는 기록 보관소(하류)다.

2확정된 요구사항

항목결정
산출물코드 우선. 승인된 화면을 피그마에 기록 (둘 다, 코드 > 디자인)
기존 자산피그마·코드에 조금씩 있으나 정리 안 됨 → 수확 후 정규화
주 사용자디자이너, 개발자, 기획/PM 등 전 직군
기술 스택여러 스택 혼재 → 토큰은 프레임워크 중립, 목업은 React 기준
비개발 직군 접점claude.ai + 커넥터, design.md를 지식으로 첨부해 사용

3핵심 원칙

① 단일 원천
git 저장소 하나(design.md + tokens + components + recipes)가 진실의 원천. 피그마 라이브러리, 목업 코드, claude.ai용 문서는 전부 파생 산출물.
② 텍스트 우선
AI가 가장 잘 읽는 형식은 마크다운 + JSON. 피그마 캔버스를 매번 MCP로 읽는 방식은 쓰지 않는다.
③ 선택지 제한
시맨틱 토큰과 등록된 컴포넌트만 사용. 임의 값(hex, arbitrary spacing) 금지. 이 제약이 일관성을 만든다.
④ 레시피 기반 조립
반복되는 페이지 유형을 레시피로 문서화. 자연어 요청 → 레시피 매칭 → 컴포넌트 조립.
⑤ 단방향 동기화
코드 → 피그마. 피그마에서의 직접 수정은 원천에 반영 안 됨. 규칙 변경은 저장소에서. (팀 공지 필요한 운영 규칙)
⑥ 규정 우선
제품별 특수 규정(도메인 규제·사내 정책·법적 요건)은 다른 모든 규칙보다 우선. regulations/<제품>.md에 명시하고, 요청이 규정과 충돌하면 AI가 생성 전에 검토 결과를 알리고 확인을 받는다.

5저장소 구조

design-system/
├── design.md               # AI 규칙서 — 시스템의 헌법
├── CLAUDE.md               # Claude Code용 절차 지침
├── tokens/
│   ├── core.json           # 원시 값: 팔레트, 타입 스케일, 간격 스케일 (W3C DTCG)
│   └── semantic.json       # 의미 토큰: bg-surface, text-primary, border-danger…
├── components/
│   ├── ui/                 # Button, Input, Table, Card, Badge, Dialog… (~15개)
│   └── patterns/           # DataTable+툴바, StatCard 그리드, AuthForm 등 조립 패턴
├── recipes/
│   ├── admin-list.md       # 어드민 테이블 리스트 페이지
│   ├── auth.md             # 로그인/가입 페이지
│   ├── dashboard.md        # 수치·지표 대시보드
│   └── form-detail.md      # 상세/편집 폼 페이지
├── regulations/            # 제품별 우선 규정 — 생성 전 필수 검토
│   └── <product>.md        # 도메인 규제·사내 정책·법적 요건 (제품별 명시)
├── playground/             # Next.js 앱 — 생성된 목업 미리보기
├── dist/
│   ├── design-standalone.md  # claude.ai 첨부용 단일 문서 (자동 생성)
│   └── tokens.css / tailwind # Style Dictionary 산출물
└── scripts/
    ├── build-tokens.ts     # 토큰 → CSS 변수 / Tailwind / 피그마 Variables
    └── build-standalone.ts # design.md+토큰+레시피 → 단일 문서

레퍼런스 구현 스택: React + Tailwind + shadcn/ui 계열. 목업·승인용이며, 토큰 JSON은 중립이므로 다른 스택 제품도 토큰을 가져다 쓸 수 있다.

6design.md 구성 — AI 규칙서

사람용 가이드라인이 아니라 AI에게 내리는 명령문 형태로 작성한다.

  1. 강제 규칙 — 색·간격·라운드·그림자는 시맨틱 토큰만 사용. 임의 값 금지 (#3B82F6, p-[13px] 등).
  2. 컴포넌트 카탈로그 — 컴포넌트마다 {언제 쓴다 / 언제 안 쓴다 / props / 예시 코드} 블록.
  3. 페이지 레시피 인덱스 — 요청 유형 → 레시피 매핑 표.
  4. 레이아웃 규칙 — 사이드바/헤더 셸, 그리드, 반응형 브레이크포인트.
  5. 금지 목록(안티패턴) — 그라데이션 남발, 카드 안의 카드, 임의 그림자 등 AI가 습관적으로 저지르는 것들.
레시피 형식 예 (admin-list): 사이드바 셸 + 페이지 헤더(제목, 주요 액션 버튼) + 필터 툴바 + DataTable + 페이지네이션. 각 구역에 사용할 컴포넌트와 토큰을 명시.

7토큰 파이프라인

원천: tokens/*.json (W3C DTCG 표준, core → semantic 참조 구조). 빌드 스크립트가 세 갈래로 산출:

  1. CSS 변수 + Tailwind 프리셋 → playground/목업용
  2. 피그마 Variables (라이트/다크 모드 포함) → Figma MCP로 주입
  3. design-standalone.md 내 토큰 표 → claude.ai용

8생성 워크플로우

원천원천과 배포 — 버전 관리

design.md를 포함한 모든 규칙의 원천은 사내 git 원격 저장소(예: GitHub) 하나다. 개인이 파일을 복사해 각자 첨부하는 방식은 금지한다 — 버전 분기가 생기는 즉시 시스템이 무너진다.

  • Claude Code 경로 — 항상 저장소를 pull 받아 사용하므로 자연히 최신 버전.
  • claude.ai 경로 — 개인 프로젝트가 아니라 팀 공유 프로젝트 1개만 운영. 프로젝트 지식은 claude.ai의 GitHub 연동(지식 동기화)으로 dist/design-standalone.md에 연결해, 저장소가 갱신되면 프로젝트 지식도 함께 갱신. 연동 불가 환경이면 "CI 빌드 → 담당자 1인이 지식 갱신"으로 대체.
  • dist/design-standalone.md는 손으로 편집하지 않는다. CI가 main 브랜치에서 자동 빌드.
  • 빌드 시 문서 머리에 버전 스탬프(버전 번호·날짜·커밋 해시)를 자동 삽입하고, 생성된 목업 하단에도 사용 버전을 표기 → 구버전 문서로 생성된 결과물을 즉시 식별.

경로 1Claude Code — 개발자·디자이너

CLAUDE.md가 절차를 강제: 페이지 생성 요청 → 해당 제품 regulations/ 검토 (충돌·주의사항 발견 시 생성 전에 알림) → design.md + 해당 레시피 읽기 → playground에 페이지 생성 → 기계 검증(lint) → dev 서버 미리보기 → 스크린샷 셀프 리뷰.

경로 2claude.ai — 기획/PM

팀 공유 claude.ai 프로젝트(위 참조)에서 대화로 요청하면 React 아티팩트로 미리보기. standalone 문서에는 규정 검토 지침과 아티팩트 제약 대응 지침 포함(토큰을 CSS 변수 블록으로 인라인, 컴포넌트는 문서 내 스니펫 사용). 결과가 채택되면 개발자/디자이너가 경로 1에서 정식 목업화.

9피그마 기록 파이프라인

  • 1회 셋업 — 토큰 → 피그마 Variables 생성, 핵심 컴포넌트 → 피그마 컴포넌트 라이브러리 생성 (figma-generate-library). Code Connect로 피그마 ↔ 코드 컴포넌트 매핑.
  • 화면 기록 — 승인된 목업 → 라이브러리 컴포넌트 인스턴스 + Variables 바인딩으로 화면 조립 (figma-generate-design). 하드코딩 값 없는 정식 산출물.
  • 재동기화 — 토큰/컴포넌트 변경 시 피그마 Variables·라이브러리 재생성.
  • 히스토리 기록 — 피그마 파일에 전용 "History" 페이지를 두고, 화면을 기록·갱신할 때마다 {날짜, 요청 내용(프롬프트 요약), 변경 사항, 디자인 시스템 버전, 승인자} 엔트리를 시간순으로 추가. 기록된 각 화면 옆에도 동일 메타를 담은 주석 카드를 붙여, 화면만 봐도 언제·왜·어떤 요청으로 만들어졌는지 추적 가능하게 한다.

10기존 자산 수확 (Phase 0)

기존 피그마 파일·코드베이스에서 실제 사용 중인 색/타이포/간격/컴포넌트를 인벤토리로 추출 → 중복 통합, 명명 정리 → 토큰과 컴포넌트 목록 초안으로 확정. 발명이 아닌 정규화.

11품질 검증

층위내용
기계 검증ESLint 커스텀 룰 또는 스크립트로 임의 색상·간격 값 검출. 생성 직후 자동 실행.
시각 검증생성 후 스크린샷을 Claude가 셀프 리뷰 (정렬, 대비, 오버플로). CLAUDE.md 절차에 포함.
사람 승인최종 게이트. 승인된 것만 피그마에 기록.

12단계별 로드맵

단계내용완료 판정
0기존 자산 수확 → 토큰 확정tokens/*.json 확정, 팀 리뷰 통과
1design.md + 레퍼런스 컴포넌트 ~15개 + playground단일 페이지 생성이 일관되게 나옴
2레시피 4종 + Claude Code 워크플로우(CLAUDE.md, lint)예시 프롬프트가 한 번에 3페이지 목업으로 나옴
3피그마 파이프라인 (Variables·라이브러리·화면 기록)승인 화면이 피그마에 정식 산출물로 기록됨
4claude.ai 접점 (standalone 빌드 + 프로젝트 셋업)기획자가 대화만으로 아티팩트 목업을 뽑음

13성공 기준

자연어 한 문단 요청 → 어드민 리스트 + 로그인 + 대시보드 3페이지가 디자인 시스템을 준수하는 동작하는 목업으로 생성되고, 승인 시 피그마에 라이브러리 기반 산출물로 기록된다.

14범위 제외 (v1)

  • 피그마 → 코드 역방향 동기화
  • 프로덕션 npm 패키지 배포 (목업·승인용 레퍼런스 구현까지만)
  • React 외 스택용 컴포넌트 구현 (토큰만 중립 제공)
  • 사내 전용 웹 툴 (claude.ai로 대체)

# spottedinprod-ds.md

spottedinprod.com에서 추출한 디자인 시스템. HiNAS DS의 시각 언어 레퍼런스로 사용한다.

- 추출일: 2026-07-29
- 출처: 스크린샷 10장 (Home, Clips, Community, Jobs 목록·상세, Search 모달, Filter 모달, Clip 상세)
- **정확도 주의**: 브라우저 실측이 아니라 스크린샷에서 역산한 값이다. 구조·패턴·비율은 신뢰할 수 있고, hex와 px는 ±1~2 오차가 있는 근사치다. 나중에 DevTools 실측값을 얻으면 수치만 교체하면 된다.

## 2. 타이포그래피

### 서체

| 환경 | 서체 | 설명 | 다운로드 |
|---|---|---|---|
| Apple 기기 (원본) | **SF Pro Text / SF Pro Display** | Apple 시스템 서체 | <https://developer.apple.com/fonts/> |
| 웹·크로스플랫폼 대체 | **Inter** | SF Pro와 가장 가까운 오픈소스 서체 | <https://rsms.me/inter/> |
| 한글 | **Pretendard** | 라틴 자소가 Inter 계열이라 혼용 시 이질감이 적다 | <https://github.com/orioncactus/pretendard> |

원본은 별도 웹폰트를 싣지 않고 `-apple-system`으로 OS 서체를 그대로 부른다. 재현할 때의 CSS 스택:

```css
font-family: -apple-system, BlinkMacSystemFont, "SF Pro Text",
             Inter, "Apple SD Gothic Neo", Pretendard, sans-serif;
```

### 스케일

| 역할 | 크기 | 굵기 | 색 | 비고 |
|---|---|---|---|---|
| 본문 | 16px | 400 | ink | line-height ≈ 1.6, 문단 간 여백 넉넉 |
| 패널 제목 | 15~16px | 400 | ink | **굵게 하지 않는다** |
| 내비 항목 | 15px | 400 | ink | 활성 시 테두리 박스 |
| 리스트 항목 | 15px | 400 | ink / muted | 비활성은 muted |
| 보조 정보 | 15px | 400 | muted | 본문과 같은 크기, 색만 다름 |
| 섹션 라벨 | 11~12px | 400~500 | muted | **대문자 + letter-spacing ≈ 0.08em** (필터 모달의 구획 라벨) |

활성 리스트 항목에는 **밑줄**을 쓴다(상세 화면의 선택된 항목). 색 변화 + 밑줄 조합.

### 그룹 라벨

패널 안에서 내용 묶음마다 붙는 작은 라벨(서체, 스케일, 팔레트 등)의 규칙:

- 색: **muted(회색)** — 다른 섹션 라벨·표의 열 헤더(th)와 동일하다. 구분은 색이 아니라 위 여백(64px)으로 한다.
- 여백: **위 64px / 아래 12px.** 위 여백을 크게 둬서 그룹 사이가 섹션처럼 끊어진다.
- 패널의 첫 그룹 라벨은 위 여백 0 (헤더 스트립에 붙는다).
- 크기·굵기·트래킹은 섹션 라벨과 동일 (11px / 400 / 대문자 +0.08em).

## 3. 선 · 테두리 · 라운드

| 항목 | 값 | 비고 |
|---|---|---|
| 선 두께 | `1px` | 예외 없음 |
| 선 색 | `--line` | 예외 없음 |
| 라운드 (채움 버튼·칩) | `3~4px` | 검정 CTA, 연회색 보조 버튼, `Esc` 칩 |
| 라운드 (**아웃라인 박스**) | `0px` | **각진 모서리.** 내비 활성 박스, 레일 hover 박스 |
| 라운드 (앱 아이콘) | `8px` | 콘텐츠 요소 |
| 그림자 | **없음** | 모달에도 없다 |

라운드 규칙이 **채움과 아웃라인에서 다르다.** 배경을 채우는 요소는 3~4px로 살짝 둥글게, 테두리만 있는 선택·hover 박스는 **각지게(0px)** 둔다. 아웃라인 박스를 둥글게 만들면 격자 선과의 각진 대비가 무너져 즉시 다른 시스템처럼 보인다.

## 5. 레이아웃

### 5-1. 앱 셸

```
┌──────────────────────────────────────────────────────┐
│  Home Clips Community [Jobs]   [Search] [Filter]  ■  │  60px, 하단 1px 선
├────────────┬────────────────────┬────────────────────┤
│ 제목  액션 │ 제목          Esc  │ 제목               │  58px, 하단 1px 선
├────────────┼────────────────────┼────────────────────┤
│            │                    │                    │
│  리스트    │      본문          │   비주얼 / 부가    │  가변, 사이 1px 선
│            │                    │                    │
├────────────┼────────────────────┼────────────────────┤
│ 9 Companies│ 7 Positions   ‹ ›  │                    │  58px, 상단 1px 선
└────────────┴────────────────────┴────────────────────┘
```

- 내비: 좌측 메뉴 / 중앙 액션 / 우측 CTA 3분할.
- 컬럼 수는 화면마다 다르다. 목록형은 2컬럼, 상세형은 3컬럼.
- 컬럼 폭은 고정 그리드가 아니라 화면별로 다르다. 관찰값: 좌 280~340px, 중앙 가변, 우 340~540px.
- **모든 컬럼이 헤더 스트립과 푸터 스트립을 공유한다.** 헤더는 `제목 + 우측 보조 액션`, 푸터는 `요약 수치 + 페이지네이션` 구조.

### 5-2. 목록 → 상세 전환

좌측에서 항목을 고르면 **페이지 전체가 스크롤되는 것이 아니라 가운데 컬럼만 바뀐다.** 가운데 헤더 스트립에 선택한 항목의 제목이 뜨고 그 아래에 해당 내용만 나타난다. 좌측 목록은 자리를 지키고 선택된 항목만 검정 + 밑줄로 바뀐다. 헤더 우측의 `Esc`로 목록 상태로 돌아간다.

### 5-3. 격자 그리드 (목록·갤러리 화면)

- 4열 그리드. 셀 사이에 gap을 두지 않고 **1px 선으로 격자를 그린다**. 카드가 아니라 표에 가깝다.
- 셀 안에는 콘텐츠(모바일 스크린샷)를 중앙 정렬하고 여백을 크게 준다.
- 커뮤니티형 셀은 상단에 `아바타 + 이름 + 셰브론` 헤더 행을 갖는다.

### 5-4. 상단 필터 레일

목록 화면에서 내비 바로 아래에 **가로 스크롤되는 아이콘 열**을 두고 하단에 1px 선을 긋는다. 높이 약 70px.

## 6. 컴포넌트 패턴

### 내비 항목
```
기본:    텍스트만, muted (진한 회색)
hover:   텍스트 ink + 연회색 채움 (--surface), 테두리 없음
활성:    텍스트 ink + 1px 테두리 박스 (radius 0 — 각짐, padding 4px 9px)
```
활성 항목의 테두리는 `--ink`가 아니라 **`--line`(연회색)** 이다. 텍스트만 검정으로 올리고 박스는 옅게 둔다.

### 버튼 (4종만 존재)
```
1. 아웃라인   1px line 테두리, 흰 배경, ink 텍스트      예) Search, Filter
2. 인버스     검정 채움, 흰 텍스트, radius 4px           예) Join SIP  — 화면당 1개
3. 보조       연회색 채움, 테두리 없음, ink 텍스트       예) Follow, Esc 칩
4. 텍스트     테두리도 채움도 없음                       예) Post a job
```
채움은 검정과 연회색 두 가지뿐이다. 컬러 버튼이 존재하지 않는다.

3번(연회색 채움)은 "누를 수 있지만 주요 행동은 아닌 것"에 쓴다. 아웃라인(1번)과 역할이 겹쳐 보이지만, 아웃라인은 **툴바의 상시 기능**에, 연회색은 **문맥 안의 보조 행동**에 쓰이는 것으로 관찰된다.

### 리스트 행
```
[아이콘 32px]  라벨          [픽셀 셰브론 ›]
```
**hover와 선택이 서로 다른 수단을 쓴다.** 이것이 이 목록의 핵심 규칙이다. 두 상태가 동시에 걸려도 서로를 가리지 않고 함께 보인다.

| 상태 | 표현 |
|---|---|
| 기본 | 라벨 muted, 박스 없음 |
| **hover** | **각진 1px 테두리 박스** (radius 0, 행 전체 폭). 라벨 색은 그대로 |
| **선택** | **라벨 ink + 밑줄, 셰브론도 ink.** 박스 없음 |
| 선택 + hover | 밑줄과 박스가 함께 나타난다 |

커맨드 팔레트(검색 모달)의 결과 목록만 다른 규칙을 쓴다. 여기서는 활성 행을 **연회색 채움**(`--surface`)으로 표시하고 테두리도 밑줄도 쓰지 않는다. 키보드로 빠르게 훑는 목록이라 덩어리로 인지되는 편이 낫기 때문으로 보인다.

- 셰브론은 기본 `#dcdcdc`로 아주 옅고, **선택 시 라벨과 함께 검정으로 올라간다.** hover에서는 색이 변하지 않는다.
- 셰브론을 텍스트와 같은 회색으로 두면 목록이 시끄러워진다. 선 색에 가깝게 낮춰 배경처럼 두는 것이 규칙이다.
- 채움을 쓸 때는 테두리를 쓰지 않고, 테두리를 쓸 때는 채움을 쓰지 않는다.

### 아이콘 — 픽셀 셰브론

이 시스템의 두 번째 서명이다. 셰브론(`›`)과 방향 화살표(`‹` `›`)가 매끈한 벡터가 아니라 **정사각형 픽셀이 계단식으로 쌓인 비트맵**으로 렌더링된다. 저해상도 비트맵 폰트의 `>` 글리프에 가깝다.

- 색: 기본 `#dcdcdc` (line gray 계열로 아주 옅게), 선택 시 검정
- 크기: 10×14px (viewBox 5×7의 정확히 2배)
- 질감: 굵고 성근 사각 픽셀 5개. 모서리에서만 닿는다
- 적용처: 리스트 행 우측, 그리드 셀 헤더 우측, 푸터의 이전·다음 화살표

### 구현 방법

**1×1 픽셀을 `x+1, y+1`로만 이어 붙인 대각선 계단을 SVG로 그려 단일 `mask-image`로 쓴다.** 픽셀끼리는 **모서리에서만 닿고 변이 겹치지 않는다.** 이 성근 연결이 원본 특유의 도트 인상을 만든다. 색은 `background-color`로 제어하므로 muted ↔ ink 상태 전환이 그대로 작동한다.

```
viewBox 0 0 5 7 · 렌더 크기 10×14px · shape-rendering=crispEdges
픽셀 하나 = 1유닛 = 정확히 2 CSS픽셀 (정수배라 뭉개지지 않는다)

rect(x, y, w=1, h=1) 5개:
(1,1) (2,2) (3,3) (2,4) (1,5)
        └ 아래로 내려가며 x+1, 꼭짓점(3,3) 이후 x-1
```

**렌더 크기는 viewBox의 정수배로 둔다.** 1.5배 같은 어중간한 배율이면 픽셀이 1px과 2px로 들쭉날쭉해져 계단이 지저분해진다.

점의 개수를 늘리거나 크기를 줄이면 굵고 성근 인상이 사라지고 그냥 가는 선처럼 보인다. **적고 굵게**가 원칙이다.

**피해야 할 방법 세 가지:**

1. **원(circle)으로 점을 찍는 것.** 둥근 점은 부드러워서 각진 픽셀 인상이 완전히 사라진다. 화살표가 아니라 굵은 점선처럼 보인다.
2. **stroke 경로에 `crispEdges`만 걸고 계단을 래스터라이저에 맡기는 것.** 계단이 기기 픽셀 단위로 잘게 생겨서 가는 회색 선처럼 보인다. 굵고 성근 도트 인상이 안 나온다. 픽셀 위치를 직접 지정해야 한다.
3. **화살표 마스크와 `radial-gradient` 도트 패턴을 `mask-composite`로 겹치는 것.** 두 마스크의 안티앨리어싱 알파가 서로 곱해져 반투명해지고, 12~14px 크기에서는 획 두께에 점이 한 줄밖에 안 들어가 거의 보이지 않는다. 색을 검정으로 올려도 알파가 이미 깎여 있어 해결되지 않는다. 브라우저별 지원 편차도 있다.

대안으로 2배 해상도 PNG를 쓸 수도 있지만, 색 상태 전환을 하려면 파일이 상태 수만큼 필요해진다.

핵심은 **셰브론이 벡터가 아니라 저해상도 비트맵처럼 보여야 한다**는 것이다.

이 픽셀 질감은 셰브론과 화살표에만 쓰인다. 다른 UI 요소는 전부 깨끗한 1px 선이다. 대비가 의도된 것으로 보인다.

### 필터 칩
```
선택:    1px 테두리 박스 (radius 4px)
비선택:  텍스트만, muted
```
같은 줄에 나열하고 간격은 약 16px. 첫 항목은 보통 `Any`.

### Esc 칩
패널·모달 헤더 우측에 배치. 텍스트 `Esc`, **연회색 채움** 배경에 muted 텍스트, radius 4px. 키보드로 닫을 수 있음을 상시 알린다. 화면에 따라 채움 없이 텍스트만인 경우도 있다.

### 모달
- 배경: **dim 아님. backdrop-filter로 강하게 blur만 건다.** 뒤 페이지 형태는 보이되 읽히지 않는 정도.
- 패널: 흰 배경, 1px 테두리, 그림자 없음, radius 거의 없음.
- 폭: 검색 모달 약 680px, 필터 모달 약 640px.
- 내부 구조: 가로 1px 선으로 구역을 나눈다. (검색 모달: 입력 → 아이콘 열 → 탭 → 결과 목록)
- 검색 입력은 테두리 없이 영역 전체를 차지하고, 아래 1px 선으로만 구분한다.

### 헤더 · 푸터 스트립
```
헤더:  [제목]                    [보조 액션 | Esc]
푸터:  [요약 수치]               [‹ Prev  Next ›]
```
컬럼마다 독립적으로 존재하며 높이를 맞춘다.

---

## 7. 인터랙션 규칙

- 상태 변화는 **테두리 유무 · 밑줄 · 연회색 채움** 셋으로만 표현한다. 색상(hue)은 바꾸지 않는다.
- **hover와 선택에 서로 다른 수단을 배정한다.** 겹쳐도 정보가 손실되지 않는다.
- 모달 진입 시 배경 blur. 닫기는 `Esc` 또는 우측 상단 칩.
- 픽셀 셰브론(`›`)은 "더 있음"의 유일한 표식이다. 화살표·플러스 등 다른 기호를 섞지 않는다.
- 로딩·빈 상태에서도 격자 선은 유지된다. 구조가 먼저 보이고 콘텐츠가 채워진다.

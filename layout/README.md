# layout/ — 레이아웃 프레임 레시피

**강제 규칙이 아니라 이름 붙은 선례이며, 페이지 유형이 아니라 레이아웃 프레임이다.**
프레임 = 화면의 껍데기(셸)와 영역 구조. 본문에 무엇이 들어가는지(위저드·상세·목록…)는
레시피가 아니라 사용자가 가져오는 스크린샷·와이어프레임이 결정한다.

생성 세션은 요청을 프레임과 **대조**하고, 맞으면 어떤 프레임인지 선언한 뒤 관례를
상속한다. 기본 질문은 하나 — "어느 프레임의 **본문**인가, 아니면 **단독 화면**인가."
애매하면 억지로 끼워맞추지 말고 **생성 전에 질문한다** (CLAUDE.md 계약).

## 등재 규칙

- 모든 레시피는 **"언제 안 쓴다"를 반드시 포함**한다.
- 사용자는 채팅에서 언제든 오버라이드할 수 있다 ("셸 빼줘" 한 마디면 됨).
- 추가·수정은 커밋으로만 = 저장소 관리자(디자이너) 승인 게이트를 지난다.
- **새 프레임(관리 콘솔과 같은 위계의 레이아웃)이 필요해지면 관리자가 파일을
  추가**하고, 365 페이지 「페이지 템플릿」 카드도 같은 번호로 함께 추가한다.
- 본문 패턴(위저드 등)은 별도 레시피로 만들지 않는다 — 해당 프레임 문서 안의
  "본문 관례 노트"로만 남긴다.
